# CDN 测速

[功能目录](README.md) · [项目首页](../../README.md)

### 指标与选择行为

测速通过脚本启动时保存的原生 fetch 发请求，绕过播放地址替换与分片调度。测速源必须是路径以 `/upgcxcode/` 开头的 UPOS 文件地址；选源时跳过 `/v1/` 等专用路径，若没有普通文件地址则整批测速显示错误，不向各手选节点拼接无效地址。目标 Host 由当前被测节点指定，并拒绝 HTTP 重定向，避免界面显示测试节点 A，实际却测到了跳转后的节点 B。

首包延迟从请求开始计时，到读取到第一个非空数据块为止，包含浏览器调度、连接与服务器等待等时间，不是 ICMP Ping。速度计算为：

```text
Mbps = 收到的字节数 × 8 / 整次请求耗时（毫秒）/ 1000
```

速度包含首包等待时间，表示本次有限样本的整体交付表现。达到首包延迟上限与最低速度两项条件才判定达标；超时或请求错误记为失败。

| 设置 | 默认 | 可设置范围 |
| --- | --- | --- |
| 最大延迟 | 100 ms | 10–60000 ms |
| 最低速度 | 10 Mbps | 0–10000 Mbps |
| 时间上限 | 3000 ms | 200–60000 ms |
| 样本大小 | 4 MiB，界面标作 MB | 0.25–16 MiB |
| 测速并发 | 3 个节点 | 1–16 个节点 |
| 使用当前视频 | 开启 | 开／关 |
| 自定义测试视频 | 留空 | BV 号、av 号或完整 B 站视频链接 |
| 测试视频分 P | 1 | 1–10000，实际需存在对应分 P |

单节点测速和“测速所选节点”会移除未达标节点，但不自动勾选原本未选中的达标节点。地区“优选”会勾选达标节点并移除未达标节点。结果附带时间戳并持久化，页面中的旧结果不表示节点当前仍有相同表现。

## 并发与取消

测速使用有并发上限的任务池，每个节点独立测量。一次任务开始时保存参数快照，避免同一批结果使用不同阈值；获取播放地址失败时不继续给每个节点制造失败记录。

取消会中止已发请求并停止安排剩余节点，保留此前完成的结果；尚未完成的节点不因本次取消而被移除。关闭面板不等同于取消测速；离开节点优选策略会取消当前测速，避免节点树隐藏后仍在后台测试节点。

多个节点并发测速共享客户端出口带宽，因此结果不能视作各节点独占带宽。并发 1 便于逐个比较；更高并发用于缩短大批节点筛选的总耗时。测速任务池与播放分片的并发设置相互独立，但实际网络资源仍然共享。

## 测试视频来源

开启“使用当前视频测速”时，使用播放器当前视频 ID 与 CID。关闭后显示自定义视频和分 P 输入项，通过普通视频信息接口查询指定分 P 的 CID，再请求播放地址。分 P 由独立输入框决定，不从视频链接的 `p` 参数自动选择；不支持 `b23.tv` 短链接。

视频字段留空时使用内置 `BV1qM4y1w716`；默认第 1 P 使用内置 CID，指定其他分 P 时查询该视频信息。自定义视频需在当前账号与地区正常可播放，无法获取指定分 P 或找不到可测速的 UPOS 地址时会显示错误。测速不生成私有签名，也不绕过账号、地区或播放权限。
