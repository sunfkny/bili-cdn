# 下载来源策略与分片开关

[功能目录](README.md) · [项目首页](../../README.md)

左侧“通用设置”中的下载来源策略为三选一，普通媒体路由与分片下载共用同一策略：

| 来源策略 | 行为 |
| --- | --- |
| 接口原有节点 | 使用播放接口提供的主备候选，不施加手选限制，也不按 PCDN 规则过滤 |
| 节点优选 | 使用右侧所选普通 CDN，不叠加 PCDN 筛选；默认策略 |
| 屏蔽 PCDN | 按规则过滤接口原有候选，不使用节点优选 |

手选节点为普通 CDN，因此“固定使用手选节点”和“在原始候选中筛除 PCDN”使用互斥策略，避免用户误以为必须同时启用两套筛选。选择节点优选后在右侧显示节点树及测速结果，左侧显示对应参数；选择屏蔽 PCDN 后以规则面板替换右侧节点树，隐藏节点优选设置；选择接口原有节点后不显示右侧面板。切换策略不清空手选节点或规则参数。

Thread Ripper 是独立的下载方式开关，默认关闭，可与三种来源策略分别组合：

| 来源策略 | 分片关闭 | 分片开启 |
| --- | --- | --- |
| 接口原有节点 | 原始候选的非分片下载 | 原始候选之间分片、竞速和救援 |
| 节点优选 | 使用手选节点的非分片下载 | 在手选节点候选之间分片、竞速和救援 |
| 屏蔽 PCDN | 使用过滤后候选的非分片下载 | 在过滤后候选之间分片、竞速和救援 |

启用某一策略会同时关闭另一个来源策略标志。读取两者同时开启的旧配置时，保留手选 CDN、关闭 PCDN 过滤；随后在界面中选择的来源策略统一保存。Thread Ripper 不受这个互斥约束。

首次安装默认选中云服务分组中的 Mirror 型 CDN。取消全部节点表示不施加手选节点限制，继续使用接口原有候选；这与“选择了节点，但这些节点均不可用”不同。后者不会自动放宽到未选节点，过滤后没有可用地址时会失败，避免回退过程中违背用户选择。

选择和播放设置影响后续请求。已经交给播放器的地址不会全部自动恢复或重新生成，重新加载视频可刷新播放信息。修改播放设置或实际变更所选节点时，会清理当前分片引擎、中止其进行中的请求并重新建立调度状态，播放器需要自行重试。
